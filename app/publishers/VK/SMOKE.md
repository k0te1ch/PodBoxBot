# VK Donut: доступ и смоук

Интеграция — официальный VK API. Раздел аудио закрыт для сторонних
приложений, а загрузка через внутренние запросы vk.com ломалась раз в месяц
(VK меняет хэши страницы), поэтому звук уходит одним из официальных способов
(`VK_MEDIA`):

- `video` (по умолчанию) — mp3 склеивается с обложкой `VK_COVER_PATH` в mp4
  и загружается в видеозаписи сообщества, в посте играет плеер. Само видео
  лежит в разделе «Видео» сообщества: если раздел открыт, запись видна и не
  донам — закройте раздел или сделайте его доступным только администраторам;
- `doc` — mp3 документом (скачивается, плеера нет; VK может не принять mp3
  как документ — проверяется смоуком);
- `none` — только текст.

Замок — `donut_paid_duration` в `wall.post`: `VK_DONUT_PAID_DURATION=-1` —
пост навсегда только для донов, число — через сколько дней он откроется всем.

## Откуда берётся ключ (`VK_AUTH_MODE`)

`wall.post` и `video.save` работают только с ключом пользователя (админа
сообщества). Есть два режима.

### token (по умолчанию)

Статичный `VK_ACCESS_TOKEN` из `.env`. Поведение как раньше: кто-то кладёт
готовый ключ, сервис им пользуется. Ключ пользователя VK живёт около часа,
поэтому этот режим подходит для разового прогона, а не для постоянной работы.

### vkid (долгоживущий доступ)

Самообновляемая пара токенов VK ID: `access_token` (1 час) + `refresh_token`
(180 дней). Вход в браузере нужен **один раз**, дальше сервис обновляет пару
сам — заранее, по ошибке авторизации и фоновой задачей раз в
`VK_MAINTENANCE_INTERVAL_HOURS` часов. Пока пара обновляется хотя бы раз в
180 дней, доступ живёт практически бессрочно. Пароль в сервис не попадает.

Настройка `.env`: `VK_AUTH_MODE=vkid`, `VK_CLIENT_ID` (номер приложения
VK ID), `VK_CLIENT_SECRET` (для конфиденциального приложения), `VK_REDIRECT_URI`
(доверенный redirect приложения). Пара токенов хранится в `VK_AUTH_FILE`
(том `secrets/vk`), сервис перезаписывает файл при каждом обновлении — нужны
права на запись.

Права `wall` и `video` для ключа пользователя VK выдаёт по запросу в
поддержку (devsupport@corp.vk.com). Без них публикация не заработает ни в
одном режиме — это ограничение VK, а не сервиса.

## Вход VK ID (режим vkid, один раз)

```sh
# 1. Ссылка согласия и code_verifier
docker compose run --rm publisher_vk python smoke.py authorize
# Откройте ссылку админом сообщества, нажмите «Разрешить»,
# скопируйте code и device_id из адреса страницы возврата.

# 2. Обмен кода на пару токенов (ввод скрытый, в историю shell не попадает)
docker compose run --rm publisher_vk python smoke.py exchange
```

Если пара всё же слетела (сменили пароль, завершили сеансы, отозвали доступ),
сервис пришлёт админам в Telegram предупреждение со ссылкой входа — повторите
эти два шага. За `VK_REFRESH_WARN_DAYS` дней до конца срока `refresh_token`
придёт напоминание заранее, пока доступ ещё рабочий.

## Проверка

```sh
# Чтение без публикации: доступ, сообщество, срок токена
docker compose run --rm publisher_vk python smoke.py check

# Тестовый пост для донов (удалите его после проверки)
docker compose run --rm -v "$PWD/test.mp3:/app/files/test.mp3" \
  publisher_vk python smoke.py publish --mp3 /app/files/test.mp3 --yes
```

После успешного прогона включите кнопку в боте: `VK_ENABLED=true`.

Ошибка авторизации (коды VK 5, 7, 15, 27, 200, 214…) приходит админу в бот с
подсказкой про доступ и не повторяется.
